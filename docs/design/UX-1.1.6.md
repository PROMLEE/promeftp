# PromeFTP 1.1.6 UX 개선 설계

기준 코드: 1.1.5 (`/Applications/PromeFTP.app`와 `source/`가 동일). 각 항목은 **원인(코드 근거) → 설계 → 수용 기준** 순서다.

## 1. 전송 내역(Transfers) 드로어

### 원인
| 증상 | 코드 근거 |
| --- | --- |
| 앱을 켜자마자 드로어가 뜸 | `transfer-service.cjs` `persist()`가 **완료된 작업까지** `sftp-transfer-queue.json`에 저장하고, `start()`가 전부 다시 불러온다. 렌더러는 `transferDrawer.hidden = transferJobs.length === 0` (`renderer.js:3157`)이라 작업이 하나라도 있으면 표시한다. 정리(보존 기간·개수 제한) 로직이 없다. |
| 지우기 버튼이 '세부정보' 안에 있음 | `renderer.js` 행 렌더링에서 `Clear`, `Pause`를 `<details class="transfer-detail">` 안에 넣는다. 전체 지우기 버튼은 없다. |
| 진행바 정렬이 어긋나고 너무 작음 | `.transfer-row`의 grid 정의가 두 곳(`style.css:664` 4열, `:711` 3열)에서 충돌한다. 진행바가 없는 행(완료·mkdir)은 열이 비어 컨트롤이 왼쪽으로 밀린다. 진행바 높이는 `5px`, 폭은 `minmax(55px,150px)`이다. |
| 완료 항목을 계속 표시함 | 설계 의도가 아니라 위 저장 방식의 부작용이다. 완료 항목에는 사용자가 할 일이 없으므로 화면에 둘 이유가 없다. |

### 설계
**원칙: 드로어는 "지금 처리 중이거나 내가 조치할 것"만 보여 주고, 나머지는 기록(History)으로 보낸다.**

1. **저장 분리**
   - `sftp-transfer-queue.json`: 아직 끝나지 않은 작업만 저장한다(`queued/running/paused/waiting-*`, `failed`, `interrupted`).
   - `sftp-transfer-history.jsonl` (신규): 끝난 작업을 한 줄씩 추가한다. 최근 500건 또는 30일을 보존한다. 경로·크기·결과·시간·오류를 남긴다.
   - 1.1.5 파일 마이그레이션: 처음 실행할 때 `completed/skipped/cancelled` 작업을 history로 옮긴다.
2. **표시 규칙**
   - 앱을 시작할 때 드로어는 닫혀 있다. 이전 실행에서 `interrupted`/`failed`가 남아 있으면 드로어 대신 상태 표시줄에 작은 배너를 띄운다: "중단된 전송 3건 · 다시 시도 · 닫기". 이때 SFTP 세션이 없으면 "연결 후 다시 시도"로 안내한다.
   - 이번 실행에서 작업을 큐에 넣으면 드로어가 열린다.
   - 모든 작업이 끝나면 4초 뒤 드로어가 자동으로 접히고, 요약 토스트("12개 파일 전송 완료 · 1개 실패 · 기록 보기")를 띄운다. 실패가 있으면 접지 않는다.
   - SFTP 도구막대에 전송 아이콘(↕, 진행 중일 때 배지)을 둔다. 누르면 드로어를 열고 닫는다. 드로어 헤더에는 `진행 중 | 기록` 세그먼트를 둔다.
3. **드로어 헤더**: `전송 · 진행 2 · 실패 1`  ……  `[완료 항목 지우기] [기록] [–]`. 지우기는 헤더에서 항상 보인다.
4. **행 레이아웃(고정 그리드, 모든 행 동일)**
   ```
   [상태아이콘 16] [이름 / 경로 1fr] [진행바 200px] [123 MB/s · 12s 120px] [액션 아이콘 72px]
   ```
   - 진행바가 없는 행에서도 해당 열을 비워 두어 정렬을 유지한다. 진행바는 높이 6px, 둥근 모서리, 폭 200px(좁은 창에서는 다음 줄 전체 폭)으로 한다.
   - 상태는 텍스트 배지 대신 색 아이콘으로 표시한다(진행=파랑 스피너, 실패=빨강, 일시정지=회색). 텍스트는 툴팁에 넣는다.
   - 행 액션은 아이콘 버튼이다: 진행 중 `⏸ ✕`, 일시정지 `▶ ✕`, 실패 `↻ ✕`. '세부정보' `<details>`는 없애고, 행을 클릭하면 경로·오류가 펼쳐진다.
   - 배치(폴더 비교)는 한 행으로 요약한다: `폴더 비교 · 34/50 · [전체 진행바]`. 펼치면 하위 항목이 나온다.
5. **CSS 정리**: `style.css:664`, `:704-713`의 중복 grid 규칙을 하나로 합친다.

### 수용 기준
- 전송 기록만 있는 상태로 재시작하면 드로어가 보이지 않는다.
- 완료 항목 지우기는 클릭 한 번으로 된다.
- 진행바가 있는 행과 없는 행에서 액션 버튼의 x좌표가 같다.
- 기록 탭에서 지난 전송을 검색할 수 있다.

## 2. SSH 세션에서 ⌘P로 스니펫이 안 열림

### 확인한 것
1.1.5 설치본을 테스트 인스턴스로 띄워 로컬 셸에서 확인했다. 메뉴 `터미널 > 스니펫 = ⌘P`, 메뉴 실행, 터미널 포커스 상태에서 ⌘P **키 이벤트(영문 `p`)** 모두 스니펫 창이 열린다.

### 유력한 원인: 한글 입력 상태
⌘P를 받는 세 경로가 모두 **`key` 문자로 비교**한다.
- `main.cjs:1803` `before-input-event`: `input.key.toLowerCase() === 'p'`
- `renderer.js:1969` xterm 핸들러: `event.key.toLowerCase()`
- 메뉴 accelerator `CmdOrCtrl+P`: Electron/macOS는 비라틴 입력 소스에서 단축키 매칭이 불안정한 것으로 알려져 있다.

SSH에서 한글을 입력하다 ⌘P를 누르면 `key`가 `'ㅔ'`가 되어 세 경로 모두 놓친다. 로컬 셸 테스트가 영문 입력 상태였기 때문에 차이가 났을 가능성이 높다.

보조 원인: `api.onCommand('snippets')`는 다른 `<dialog>`가 열려 있으면 무시한다(`renderer.js:3664`). 인증·호스트 키 대화상자가 `open` 상태로 남아 있으면 SSH에서만 막힌다.

**확인 방법**: SSH 세션에서 한/영을 영문으로 바꾸고 ⌘P를 눌러 본다. 열리면 원인 확정이다.

### 설계
1. **물리 키(code) 기준 매칭**: `input.code === 'KeyP'` / `event.code === 'KeyP'`로 바꾼다. 같은 방식으로 ⌘F, ⌘K, ⌘D, ⌘= 등 renderer와 main의 모든 수동 단축키를 code 기준으로 통일한다(공용 `matchShortcut(event, 'Meta+KeyP')` 헬퍼).
2. **다른 대화상자 처리**: 열린 dialog가 *모달 입력 중*(인증 프롬프트)일 때만 무시한다. 그 밖의 경우에는 기존 dialog를 닫고 스니펫을 연다.
3. **대체 키**: 위 수정 뒤에도 ⌘P가 시스템이나 다른 앱과 충돌하면 대체 키를 쓴다.
   - 기본 대체 키는 **⌘⇧P**다(명령 팔레트 관례, code 매칭). ⌘P와 ⌘⇧P는 둘 다 동작한다.
   - 장기적으로는 Preferences → Shortcuts를 "보기 전용"에서 **스니펫·트리거·찾기 단축키 재지정**으로 확장한다. 저장은 `state.shortcuts`, 충돌하면 경고한다.
4. **진단 로그**: 디버그 모드에서 단축키가 매칭되지 않을 때 `key/code/IME 조합 여부`를 로그로 남긴다.

### 수용 기준
- 한글 입력 상태의 SSH 세션에서 ⌘P와 ⌘⇧P가 스니펫을 연다.
- 비모달 대화상자가 열려 있어도 스니펫이 열린다.

## 3. 무한 스크롤백 vs 최대 줄 수 (답변 + 문구 개선)
- **최대 줄 수**(100–100,000, 기본 20,000): 화면 위로 올라간 출력을 그 줄 수만큼 메모리에 보관한다. 넘치면 가장 오래된 줄부터 버린다. 메모리 사용량이 일정하다.
- **무한 스크롤백**: 세션이 열려 있는 동안 출력을 버리지 않는다(`scrollback: Infinity`). 긴 로그를 `tail -f` 하면 메모리가 계속 늘어난다. 켜면 줄 수 입력은 비활성화된다.
- 둘 다 메모리에만 저장되고 세션을 닫으면 사라진다.

**UI 개선**: 체크박스 + 숫자 입력을 세그먼트 `[제한 | 무제한]`로 바꾸고, 제한일 때만 줄 수를 표시한다. 무제한에는 ⓘ 툴팁 "출력을 버리지 않아 오래 열어 두면 메모리가 계속 증가합니다"를 단다.

## 4. PAM 규칙 vs 저장된 응답 (답변 + 화면 개선)
| | 전역 PAM 규칙 | 저장된 응답 |
| --- | --- | --- |
| 범위 | **모든 호스트** | **특정 호스트(연결) 하나** |
| 만드는 방법 | 설정에서 직접 추가 | 로그인 성공 후 "응답 저장" |
| 질문 매칭 | 정확히 일치 또는 정규식 | 그 호스트에서 받은 질문 그대로 |
| 용도 | 회사 공통 OTP 질문, `Password:` 같은 공통 패턴 | 특정 서버 전용 계정 질문 |

관련 스위치 두 개는 의미가 다르다.
- **"연결할 때 저장된 PAM 응답 불러오기"**(`useStoredAuthOnConnect`): 전역 규칙과 저장된 응답 **모두**를 쓰는 마스터 스위치다. 끄면 둘 다 사용하지 않는다.
- **"저장된 응답 자동 전송"**(`useSavedRepliesAutomatically`): 켜면 바로 전송하고, 끄면 입력란에 미리 채운 뒤 확인을 기다린다. 저장된 응답에만 적용된다.

**UI 개선**: 이름이 헷갈리므로 바꾼다.
- 마스터 스위치는 "저장된 인증 정보 사용"으로 바꾸고 섹션 맨 위로 옮긴다. 끄면 아래 섹션 전체를 흐리게 표시한다.
- "전역 PAM 규칙"은 "모든 호스트 규칙", "저장된 응답"은 "호스트별 응답"으로 바꾼다.
- 각각 ⓘ 툴팁을 단다(5번 패턴).

## 5. 에이전트 탭: 접근 권한 저장 실패 + 항목별 도움말

### 저장 실패 원인 (코드 근거)
`Save Access`는 `agent-grant` → `agentService.grant()` → `transport.validateGrant()`를 거친다. 다음 경우 예외가 발생한다.
1. **"SFTP 탐색 허용"이 기본으로 켜져 있는데 원격 디렉터리를 비워 두면** `remotePath('')`가 `INVALID_PATH`를 던진다. SSH 명령만 허용하려는 사용자가 가장 먼저 겪는다.
2. 작업 이름이 `^[a-z0-9][a-z0-9_-]{0,63}$`에 맞지 않으면 `INVALID_TASK`다(대문자, 공백, 한글 불가).
3. 작업 이름 또는 고정 명령 중 하나만 입력해도 실패한다.
4. SFTP를 끄고 작업도 명령 승인도 없으면 `INVALID_REQUEST`다.

**결정적인 UX 버그**: 오류는 탭 **맨 위** `#agent-message`에 `Error invoking remote method 'agent-grant': Error: INVALID_PATH` 형태의 원문 코드로 표시된다. 저장 버튼은 화면 아래에 있어 사용자는 오류를 보지 못하고 "저장이 안 된다"고 느낀다. 성공해도 확인 표시가 없다.

### 설계
1. **인라인 검증**: 저장 전에 렌더러에서 같은 규칙을 검사한다. 해당 필드 바로 아래에 빨간 한 줄 메시지를 표시하고 그 필드에 포커스한다.
   - 원격 디렉터리: "SFTP를 허용하려면 /로 시작하는 경로를 입력하세요"
   - 작업 이름: "소문자·숫자·-·_만, 64자 이내"
   - 작업 쌍: "작업 이름과 고정 명령을 함께 입력하세요"
2. **오류 코드 번역 표**: `INVALID_PATH`, `INVALID_TASK`, `PROFILE_NOT_ELIGIBLE`, `ACCESS_DENIED`(북마크가 바뀜), `INVALID_REQUEST` → 현지화 문장. IPC 접두어(`Error invoking remote method…`)를 제거한다.
3. **결과 표시는 버튼 옆에**: `[접근 저장] ✓ 저장됨 (14:02)` / `⚠ 저장 실패: …`.
4. **기본값 조정**: "SFTP 탐색 허용"을 기본 꺼짐으로 바꾼다. 켜면 원격 디렉터리와 다운로드 필드가 나타난다(지금은 비활성화만 됨). 섹션을 `SFTP` / `SSH 명령` / `인증·트리거` 세 그룹으로 나눈다.

### 항목별 ⓘ 툴팁
- **패턴**: 레이블 오른쪽에 14px `ⓘ` 버튼을 둔다. hover, focus, 클릭으로 열리는 팝오버(최대 260px, 1–2문장)이며 Esc로 닫힌다. 기존 장문 `?` 토글 2개(`agent-token-help`, `agent-profile-help`)는 이 패턴으로 쪼갠다.
- **접근성**: `aria-describedby`로 연결하고, 키보드 Tab으로 이동할 수 있게 한다.
- 공용 컴포넌트 `infoTip(text)`로 만들어 3·4번 설정에도 재사용한다.

| 항목 | 툴팁 문구 |
| --- | --- |
| 로컬 에이전트 접근 사용 | 이 Mac의 AI 에이전트가 PromeFTP CLI로 연결할 수 있게 합니다. |
| 클라이언트 등록 | 에이전트마다 별도 토큰을 발급합니다. 토큰은 한 번만 표시됩니다. |
| 저장된 토큰 지우기 | CLI가 자동으로 읽던 로컬 토큰 파일을 삭제합니다. |
| 클라이언트 폐기 | 이 클라이언트의 토큰과 모든 북마크 권한을 취소합니다. |
| 북마크 | 이 북마크의 SSH 설정(alias, ProxyJump 포함)으로 연결합니다. |
| SFTP 탐색 허용 | 지정한 폴더 아래만 목록 조회·정보 확인을 허용합니다. 수정은 불가합니다. |
| 원격 디렉터리 | 에이전트가 볼 수 있는 최상위 경로입니다. /로 시작해야 합니다. |
| 다운로드 허용 | 파일당 16 MiB까지 앱 전용 임시 폴더로 받습니다. |
| 저장된 인증 사용 | 이 호스트에 저장된 PAM 응답을 에이전트 연결에도 씁니다. |
| 승인 후 SSH 명령 허용 | 에이전트가 요청한 명령은 매번 확인 창에서 승인해야 실행됩니다. |
| 작업 이름 / 고정 명령 | 승인 없이 실행할 수 있는 명령 하나를 이름으로 등록합니다. |
| PAM 규칙 | 에이전트 연결에서 쓸 수 있는 모든 호스트 규칙을 고릅니다. |
| 알림 트리거 | 출력이 일치하면 에이전트에 이벤트로 알립니다. 자동 응답은 하지 않습니다. |
| 보존 기간 | 활동 기록을 1–90일 보관합니다. 명령 내용과 비밀번호는 기록하지 않습니다. |

## 6. 앱 정보 탭

### 현재 문제
제목 2개(소프트웨어 업데이트, 라이선스), 버튼 7개가 같은 무게로 나열되어 있다. 버전과 플랫폼이 회색 메모로 흩어져 있고, 라이선스 문구가 본문 수준으로 노출된다.

### 벤치마크
- **macOS 표준 About 패널**(Finder, Xcode): 중앙 정렬, 아이콘 → 이름 → 버전 → 저작권 한 줄로 끝난다.
- **iTerm2 / Transmit / Tower**: 업데이트는 별도 섹션으로 두되 "자동 업데이트 토글 + 지금 확인 + 마지막 확인 시각" 한 묶음으로 처리한다.
- **VS Code / Raycast**: 버전 정보 "복사" 버튼(버그 리포트용)이 있고, 링크는 텍스트 링크로 둔다.

### 설계 (650px 창 기준)
```
              [앱 아이콘 72px]
                 PromeFTP
        버전 1.1.5 (Apple Silicon)  [복사]
      SSH와 SFTP를 하나의 macOS 작업 공간에서

 ┌ 업데이트 ──────────────────────────────┐
 │ ✓ 최신 버전입니다 · 마지막 확인 14:02     [지금 확인] │
 │ [■] 자동으로 업데이트 설치                         │
 │     활성 세션이 끝난 뒤 설치됩니다.                  │
 └────────────────────────────────────────┘

   릴리스 노트 · 사용 가이드 · GitHub · 개발 후원

   © 2026 Promlee · MIT 라이선스 · 오픈소스 고지
```
- 정체성 영역은 중앙 정렬한다. 버전과 플랫폼을 한 줄로 합치고, "복사"는 `PromeFTP 1.1.5 · macOS 26.x · arm64`를 클립보드에 복사한다.
- 업데이트는 카드 하나로 묶는다. 상태 아이콘과 문구, 버튼 하나, 토글 하나만 둔다. 업데이트가 있으면 버튼이 "1.1.6 설치"로 바뀐다.
- 외부 링크 4개는 버튼 대신 가운데 점(·)으로 구분한 텍스트 링크 한 줄로 바꾼다.
- 라이선스는 하단 작은 글씨 한 줄로 줄인다. "MIT 라이선스"와 "오픈소스 고지"를 누르면 기존 두 창이 열린다. "Electron (MIT) · xterm.js (MIT)" 문구는 고지 창으로 옮긴다.
- 제목(h3)은 "업데이트" 하나만 남긴다.

## 작업 순서 제안
1. **2번 ⌘P 수정**: 작은 변경이고 체감 효과가 크다. 한글 입력 상태 재현으로 원인을 먼저 확정한다.
2. **5번 저장 오류 표시와 인라인 검증**: 버그 성격이다. 툴팁은 같은 PR에서 컴포넌트로 만든다.
3. **1번 전송 드로어**: 저장 구조 변경과 마이그레이션이 필요해 가장 크다.
4. **6번 앱 정보, 3·4번 문구와 툴팁**: 1번의 툴팁 컴포넌트를 재사용한다.
