# PromeFTP 1.1.9

## What's new

- Agents: a bookmark's agent access has a new "Trust host keys automatically" setting. It is off by default.
  - **Off (ask me):** a new or changed host key opens a confirmation dialog.
  - **New keys only:** a key PromeFTP has never seen for the server is trusted without asking.
  - **New and changed keys:** a key that differs from the trusted one is also trusted without asking.
  Turning it on shows a warning: if the connection is intercepted, saved passwords and answers can be sent to an attacker automatically. Choosing "New and changed keys" asks for a second confirmation.
- Agents: keys trusted automatically are stored for agents only and do not change the keys the app trusts. Each automatic trust is recorded in the activity history with the previous and new fingerprints, and agents see a `hostkey.autotrusted` event.
- Agents: an old key in `~/.ssh/known_hosts` or `/etc/ssh/ssh_known_hosts` no longer stops a connection before PromeFTP can ask. PromeFTP reads these files but never changes them. If a file cannot be read, the key is treated as changed and you are asked to confirm it.
- Agents: while you enter a one-time password (OTP), the authentication time limit is extended to 3 minutes from the prompt, up to 10 minutes after the connection starts.
- Agents: `promeftp session wait --session ID` waits up to 25 seconds and returns as soon as the session status changes. Status responses tell the agent to keep waiting while a connection or prompt is pending, and closed sessions include the next steps for each reason.
- Agent skill: explains how to keep a session open while you enter an OTP, how to reuse one session for several tasks, and what each end reason means.

## Known issues

- The activity history in Settings shows the five most recent entries, so frequent status checks can push older entries such as automatic trust out of view.
- Some labels in Korean, Japanese, and Chinese are machine translated and may read awkwardly. A few activity labels are shown in English.
- A bookmark that uses an SSH alias or a different HostName may show an "untrusted host key" banner even when the key is trusted.

## Update notes

- Close active sessions before updating.
- Requires macOS 13 or later on Apple Silicon.
- Reinstall or update the agent skill to get the new waiting instructions. See [agent setup](../AGENTS.md) and [troubleshooting](../TROUBLESHOOTING.md).
