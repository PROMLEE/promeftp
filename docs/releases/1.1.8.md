# PromeFTP 1.1.8

## What's new

- Agents: saved passwords and saved answers are filled in the same way as in the app. When "Use saved authentication" is on for a bookmark, all of your authentication rules apply, as they do in the app.
- Agents: when "Use saved authentication" and the app's OpenSSH Keychain option are both on, agents can use key passphrases stored in the Keychain.
- Agents: when an agent cannot answer an authentication prompt automatically, the prompt event says why, for example no saved answer or saved authentication not granted.
- Agents: a stale key in `~/.ssh/known_hosts` no longer blocks a server whose current key you trusted in PromeFTP. PromeFTP reads `~/.ssh/known_hosts` but never changes it.
- Agents: when a server's host key is new or has changed, PromeFTP asks you to confirm it in a dialog that shows the previous and new fingerprints. The dialog does not require opening the app window. If you decline or do not answer within 60 seconds, the agent receives `HOST_KEY_UNCONFIRMED`.
- Agents: failed requests include `error.next`, a list of the steps the agent can take next.

## Known issues

- If a server's key changed and you never trusted the new key in PromeFTP, and the old key is still in `~/.ssh/known_hosts`, the agent reports `HOST_KEY_CHANGED` without showing the dialog. Check the new fingerprint, then connect once in PromeFTP to trust it.
- Some labels in Korean, Japanese, and Chinese are machine translated and may read awkwardly.
- A bookmark that uses an SSH alias or a different HostName may show an "untrusted host key" banner even when the key is trusted.

## Update notes

- Close active sessions before updating.
- Requires macOS 13 or later on Apple Silicon.
- See [agent setup](../AGENTS.md) and [troubleshooting](../TROUBLESHOOTING.md).
